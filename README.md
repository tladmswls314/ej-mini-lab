# EJ MINI LAB 학교용 서버 배포 준비판

## 현재 상태

학교용 아이디·비밀번호 방식의 서버 코드를 구현하고 테스트했습니다. **실제 인터넷 운영 서버는 아직 배포하지 않았고 학생용 접속 주소도 발급되지 않았습니다.** Render 계정 연결, 요금 승인, 배포 후 HTTPS·모바일 검증이 남아 있습니다. ChatGPT 계정은 학생 로그인에 사용하지 않습니다.

기존 1~10회 지문·해석·핵심 구문과 학습 기능을 유지했습니다. 이 폴더에는 학생 기록 DB와 교사 비밀번호가 없습니다. 공개 테스트 계정도 자동 생성하지 않습니다.

## 선생님이 준비할 것

1. ChatGPT에서 Render를 설치하고 본인 계정에 연결합니다. 비밀번호·API 키는 채팅에 붙여 넣지 마세요.
2. 실제 청구 조건을 확인하고 호스팅 비용을 승인합니다. 현재 검토한 최소 구성은 Starter $7/월 + 영구 디스크 1GB $0.25/월 = 약 $7.25/월입니다. 세금·환율·초과 트래픽·추가 서비스는 별도입니다. 최종 금액은 가입 계정의 청구 화면에서 확인해야 합니다.
3. 교재 파일을 포함하므로 소스 저장소는 비공개로 연결합니다. Render에 연결할 비공개 Git 저장소 또는 다른 지원 배포 경로가 필요합니다. 현재 연결된 저장소는 없습니다.
4. 배포 시 교사용 첫 비밀번호를 비밀 환경변수에 직접 설정합니다. 교사가 로그인한 뒤 콘텐츠를 검수·승인하고 학생 계정을 발급합니다.

서버 배포는 위 연결·비용 승인을 받은 후 진행합니다. 서버 파일을 업로드했다고 운영이 시작된 것으로 보지 마세요.

공식 근거(2026-11-10 확인): https://render.com/pricing , https://render.com/docs/disks , https://render.com/docs/deploy-flask

## 새로 구현한 기능

- 교사: 학생 계정 발급, 임시 비밀번호 재발급, 계정 중지·재개, 중지 계정과 기록 삭제, 담당 학생 기록 JSON 내보내기.
- 학생: 처음 로그인/초기화 후 비밀번호 변경 필수, 본인 비밀번호 변경, 본인 기록만 접근.
- 임시 비밀번호는 무작위로 생성되어 발급 직후 한 번 표시합니다. 평문 비밀번호는 DB에 저장하지 않습니다.
- 비밀번호 변경·초기화·중지는 해당 학생의 모든 기존 로그인을 무효화합니다.
- Secure/HttpOnly/SameSite 쿠키, 동일 출처 확인과 CSRF 토큰, 로그인 실패 제한, 검색 색인 방지, 콘텐츠 서버측 보호.
- 교재 10문항은 모두 유효할 때 한 번에 저장합니다. 잘못된 답안은 일부만 저장되지 않습니다.
- 단어시험 중복·동시 제출 시 1회만 기록합니다.
- DB 백업 명령과 관리 작업 감사 기록.

## 배포 설정 (개발 담당자용)

`render.yaml`은 유료 리소스 설정입니다. 승인 없이 실행하지 마세요.

- Python 웹 서비스 / build: `pip install -r requirements.txt`
- start: `sh start.sh` (Gunicorn 2 workers × 2 threads)
- Health: `/healthz`
- 영구 디스크: `/var/data`, 1GB
- `MINI_DB=/var/data/mini.sqlite3`
- `MINI_SECURE=1`
- `APP_ORIGIN=https://실제-서비스-주소` — 끝의 `/` 없이 실제 HTTPS 도메인만 입력
- `BOOTSTRAP_TEACHER_ID=ejteacher`
- `BOOTSTRAP_TEACHER_PASSWORD`: 문자·숫자 포함 12자 이상 비밀 환경변수. 최초 초기화 후 삭제해도 됩니다. 기존 교사가 있으면 재시작 시 비밀번호를 덮어쓰지 않습니다.

DB 초기화는 디스크가 연결된 시작 시점에 실행합니다. build나 pre-deploy 단계에서 DB를 생성하지 마세요. 단일 인스턴스용 SQLite입니다. 다중 서버 확장에는 PostgreSQL 이전이 필요합니다. 배포 중 짧은 중단이 있을 수 있습니다.

Dockerfile도 제공합니다. 컨테이너는 비관리자 계정으로 실행하며 `/data` 쓰기 권한과 영구 볼륨이 필요합니다. Docker 이미지 빌드 및 실제 호스팅 배포는 미검증입니다.

## 로컬 검토만 할 때

Python 3.10 이상을 사용합니다. Windows PowerShell에서 폴더를 연 뒤:

```powershell
$env:MINI_SECURE="0"
python manage.py create-teacher
python server.py
```

`http://127.0.0.1:8000/`에 접속합니다. 교사 아이디는 `ejteacher`, 비밀번호는 방금 직접 설정한 값입니다. 이 방법은 외부 운영용이 아닙니다. 외부에서는 `MINI_SECURE=0`을 사용하지 마세요.

## 교사 운영 순서

1. 콘텐츠 관리에서 1~10회 자료를 읽고 회차별로 승인합니다.
2. 학생 관리에서 수강 회차(1·2차), 반(A·B), 아이디, 별칭을 입력해 계정을 발급합니다.
3. 학생에게 아이디·임시 비밀번호·배포된 접속 주소를 개별 전달합니다.
4. 학생은 첫 로그인 때 비밀번호를 바꾼 뒤 다시 로그인합니다.
5. 교사 현황에서 미응시·복습 미완료·추가 설명 요청과 오답을 확인합니다.
6. 분실한 비밀번호는 학생 관리에서 초기화합니다. 학생이 다시 변경해야 합니다.
7. 수업 종료 후 학교에서 정한 보존기간을 적용하고 계정 중지, 백업, 필요한 기록 삭제를 진행합니다.

## 백업·복구

관리 서버의 보안 터미널에서:

```sh
python manage.py backup --output /var/data/backups/날짜.sqlite3
```

SQLite 온라인 백업을 사용합니다. 감사 기록·계정·학습 기록이 포함되므로 권한을 제한하세요. 서버와 다른 안전한 위치로 백업을 내려받아 보관해야 합니다. **자동 백업 일정과 외부 백업 저장소는 아직 연결하지 않았습니다.** 디스크 스냅샷만을 DB 백업으로 간주하지 마세요.

복구: 서비스를 중지하고 현재 DB의 사본을 보관한 뒤 검증된 백업으로 교체합니다. 복구 전 `PRAGMA integrity_check`를 수행하고, 복구 후 재접속·학생 기록을 검증하세요. 백업에는 로그인 세션도 포함되므로 복구 시 sessions 테이블을 비워 재로그인을 요구해야 합니다. 이 패키지 테스트는 백업 생성·무결성과 동일 DB 재시작을 확인했으며, 원격 재해 복구 훈련은 하지 않았습니다.

교사 비밀번호 분실: 보안 터미널에서 `python manage.py reset-teacher --user ejteacher` 실행 후 직접 입력합니다.

## 학교 사용 전 확인

- 학교의 외부 서비스 사용 승인과 처리 목적·수집 항목·보존기간·삭제 담당자 확정
- 호스팅 지역(설정안은 싱가포르)과 국외 저장 적합성, 위탁·개인정보 처리 안내를 학교 담당자와 확인
- 실명·전화번호 없이 수업용 별칭과 최소 계정 정보로 운영
- 교재 온라인 제공 범위 최종 확인 및 비공개 소스 저장소 사용
- 교사 계정, 호스팅 계정의 보안 설정과 백업 담당자 지정
- 배포 후 실제 HTTPS, 스마트폰·학교망, 학급 동시접속 및 데이터 복구 확인

이 항목은 법적 적합성 인증이나 전문 보안감사를 대체하지 않습니다. 개발에는 가상 데이터만 사용했습니다.
